## Step 1: Contract (lead)
Gateway routes (not in the query API): `POST /gateway/anthropic/v1/messages`, `POST /gateway/anthropic/v1/messages/count_tokens`,
`GET /gateway/anthropic/v1/models`, `POST /gateway/openai/v1/chat/completions`, `GET /gateway/openai/v1/models`.
Query side: `GET /v1/gateway/turns?from&to&client&limit&cursor&since` → turns (one per llm span with
source=gateway) and `GET /v1/gateway/summary?from&to` → per-client totals. New `Attr` keys:
`lucentpad.gateway.upstream`, `lucentpad.ttfb_ms`, `lucentpad.key_fingerprint`. `make contract`.

## Step 2: Gateway proxy (backend agent) — **Owns:** `server/lucentpad_server/gateway/`
- httpx `AsyncClient` per upstream (HTTP/2 off by default, keep-alive pool). Forward method, path, query, body and
  headers except hop-by-hop; **never log or store** `x-api-key` / `Authorization`; only a salted SHA-256
  fingerprint (first 12 hex) goes on the span, salt from `LUCENTPAD_KEY_SALT` (random per install).
- Streaming: return a `StreamingResponse` that yields each upstream chunk **as it arrives, unmodified**; a
  tee parses SSE on the side (Anthropic `message_start`/`message_delta` usage; OpenAI `usage` chunk, only
  when the client asked for it, never inject it: byte-identical output is the rule) and builds the span
  off the response path (spans go to the in-process ingest queue, never awaited on the hot path).
- Non-streamed: read, record, return. Failover per D18 on 429/5xx for non-streamed only.
- Span: `kind=llm`, `source=gateway`, `lucentpad.client` from User-Agent (`claude-code`, `copilot-cli`,
  `copilot-chat`, else `other`), session grouping per D16 (root `kind=agent` span per session, updated as
  turns arrive), previews per D6 (last user message / answer, capped), `lucentpad.ttfb_ms`.
- Errors: upstream errors are passed through verbatim with status; gateway-side failures → 502 with a
  JSON body in the provider's error shape.

**Acceptance:** tests with a fake upstream (httpx MockTransport / local ASGI app): byte-identical streamed
bodies for both providers incl. tool-use streams; client disconnect mid-stream closes upstream; headers
forwarded, keys never in spans/logs (grep the captured logs); failover on 429/503 non-streamed only;
session grouping; usage parsed from both stream formats; a benchmark test shows added p95 < 10 ms
per request against a local fake upstream (PRD target).
